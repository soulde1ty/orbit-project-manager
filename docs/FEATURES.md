# Возможности Orbit

Orbit помогает организовать работу команды: от первых задач и назначения исполнителей до анализа прогресса и сравнения результатов. Интерфейс доступен на русском и английском языках.

## Основные функции

| Возможность | Как работает |
| --- | --- |
| Вход по email и паролю | Сервер проверяет пароль и создаёт сессию в HttpOnly cookie |
| Проекты и команда | Даты, участники и статусы active, paused, completed и archived |
| Управление задачами | Карточка задачи, канбан и список с исполнителем, приоритетом и дедлайном |
| Учёт выполнения | Исполнитель обновляет часы, статус и прогресс своей задачи; права проверяются сервером |
| Подзадачи и зависимости | Чек-лист и связи между задачами одного проекта |
| Обсуждения | Комментарии в карточке задачи с автором и временем |
| Ближайший шаг | Подсказка на главной странице с учётом блокировок, сроков, риска и назначения задачи |
| Оценка риска | RiskScore с объяснением пяти факторов |
| План, факт и нагрузка | Сравнение прогресса и трудозатрат, оставшиеся часы работы команды |
| Контрольные снимки | Сохранение показателей проекта и сравнение двух моментов времени |
| История | Журнал действий с автором и временем |
| Поиск и экспорт | Фильтры задач и выгрузка текущей выборки в CSV |
| Локальный запуск | JSON-файл без внешней базы, MongoDB или Docker Compose |

## Формула риска

Риск задачи рассчитывается по формуле:

```text
RiskScore = 0.30 × D + 0.25 × P + 0.20 × W + 0.15 × B + 0.10 × A
```

Здесь D: риск дедлайна, P: отставание прогресса, W: перегрузка исполнителя, B: блокировка и A: неактивность. Каждый компонент и итог находятся в диапазоне 0…1. Это эвристический показатель для приоритизации внимания менеджера, а не статистическая вероятность срыва срока.

Правила нормализации и границы low, medium и high описаны в [архитектуре](ARCHITECTURE.md). Завершённая задача имеет нулевой риск.

## Правила работы

- Переключатель RU / EN меняет язык интерфейса. Названия проектов, задач и другие введённые пользователями данные не переводятся автоматически.
- В API фактические часы передаются в `actualHours`, прогресс в `progress`, а оценка риска в вычисляемом объекте `risk`.
- Orbit использует серверные сессии в HttpOnly cookie; токен доступа не хранится в JavaScript или localStorage.
- Статусы paused, completed и archived позволяют сохранять неактивные проекты. Архивация сохраняет задачи и историю, удаление: отдельная операция с удалением связанных данных.
- JSON-хранилище позволяет работать локально без установки базы данных. Для MongoDB предусмотрен отдельный адаптер хранения.
- В режиме MongoDB endpoint аналитики использует aggregation pipeline для сводных показателей и распределения задач по статусам. RiskScore, плановый прогресс, нагрузка и снимки используют общий серверный модуль. Рабочий набор данных хранится в памяти одного процесса, что ограничивает горизонтальное масштабирование.
- Сигнал о переходе редактируемой задачи в высокий риск хранится как событие `risk.high`. Отдельная коллекция `risk_alerts`, фоновая рассылка и наблюдение за переходами риска всех зависимых задач не реализованы.
- Метрики вычисляются из текущих задач. Исторические значения появляются при сохранении снимков; приложение не создаёт вымышленную историю производительности.
