# HTTP API Orbit

Базовый адрес локального сервера: `http://127.0.0.1:3000`. Тело запросов и ответы используют JSON. Для запросов с телом нужен `Content-Type: application/json`. Маршруты, кроме health, config, login и logout, требуют cookie сессии `orbit_session`, которую сервер устанавливает при входе. Срок сессии: 12 часов; перезапуск сервера завершает все сессии.

## Маршруты

| Метод и путь | Назначение и ответ |
| --- | --- |
| `GET /api/health` | Проверка сервера: `{status, storageMode}` |
| `GET /api/config` | Доступность демонстрационного входа: `{demoMode}` |
| `POST /api/auth/login` | `{email, password}` → `{user}` и cookie |
| `POST /api/auth/logout` | Завершение сессии → `{ok: true}` |
| `GET /api/auth/me` | Текущий пользователь → `{user}` |
| `GET /api/bootstrap` | Доступные `user`, `projects`, `tasks`, `members`, `events`, `snapshots`, `storageMode` |
| `GET /api/projects` | Массив доступных проектов |
| `POST /api/projects` | Создание проекта → проект, HTTP 201 |
| `PATCH /api/projects/:id` | Частичное изменение проекта → проект |
| `DELETE /api/projects/:id` | Удаление проекта, его задач, событий и снимков → `{ok: true}` |
| `GET /api/tasks?projectId=…` | Массив задач с вычисленным `risk`; фильтр необязателен |
| `POST /api/tasks` | Создание задачи → задача с `risk`, HTTP 201 |
| `PATCH /api/tasks/:id` | Частичное изменение задачи → задача с `risk` |
| `DELETE /api/tasks/:id` | Удаление задачи и ссылок на неё в зависимостях → `{ok: true}` |
| `POST /api/tasks/:id/comments` | `{text}` → созданный комментарий, HTTP 201 |
| `POST /api/snapshots` | `{projectId, name}` → сохранённый снимок, HTTP 201 |
| `DELETE /api/snapshots/:id` | Удаление снимка → `{ok: true}` |
| `GET /api/analytics/:projectId` | Сводные показатели проекта и `workload`; в MongoDB также `statuses` |
| `POST /api/members` | Создание участника → профиль без хеша пароля, HTTP 201 |
| `PATCH /api/members/:id` | Изменение профиля → профиль без хеша пароля |

Проекты, задачи и снимки доступны участникам проекта и администраторам. Создание и удаление этих объектов требуют роли manager или admin. Исполнитель может менять только `status`, `progress`, `actualHours` и `subtasks` собственных задач; комментарий может добавить любой участник проекта.

Менеджер создаёт пользователей только с ролью member и может редактировать их профиль. Роли и пароли других существующих пользователей меняет администратор. Менеджер может поменять собственный пароль. Изменение пароля аннулирует сессии этого пользователя. Созданный без пароля участник доступен для назначения задач, но не может войти в систему.

## Примеры тел запросов

Создание проекта:

```json
{
  "name": "Customer Portal",
  "description": "Портал поддержки клиентов",
  "color": "#6366f1",
  "status": "active",
  "startDate": "2026-11-02",
  "dueDate": "2026-12-01",
  "memberIds": ["u-demo", "u-anna"]
}
```

Идентификаторы участников берутся из `/api/bootstrap`. В демонстрационной базе присутствуют `u-demo` и `u-anna`; в чистой базе используйте фактически возвращённые значения. Создатель автоматически включается в состав нового проекта.

Создание задачи: замените `project-id-from-api` на идентификатор созданного проекта:

```json
{
  "projectId": "project-id-from-api",
  "title": "Согласовать макет страницы",
  "description": "Проверить состояния загрузки и ошибки",
  "status": "in_progress",
  "priority": "high",
  "assigneeId": "u-anna",
  "startDate": "2026-11-02",
  "dueDate": "2026-11-09",
  "plannedHours": 12,
  "actualHours": 3,
  "progress": 25,
  "dependencies": [],
  "subtasks": [
    {"id": "check-loading", "title": "Состояние загрузки", "done": true},
    {"id": "check-errors", "title": "Состояние ошибки", "done": false}
  ]
}
```

Обновление выполнения задачи:

```json
{"status": "review", "progress": 90, "actualHours": 10}
```

Комментарий:

```json
{"text": "Макет готов к проверке, осталось согласовать текст ошибки."}
```

## Ограничения данных

Даты передаются в формате `YYYY-MM-DD`; начало не может быть позже окончания. Прогресс находится в диапазоне 0…100, часы: 0…100000, вместимость участника: 1…168 часов. Статус done устанавливает прогресс 100. Исполнитель должен входить в проект; пустой `assigneeId` означает отсутствие назначенного исполнителя.

Статусы задач: `todo`, `in_progress`, `review`, `done`, `blocked`. Приоритеты: `low`, `medium`, `high`, `urgent`. Статусы проектов: `active`, `paused`, `completed`, `archived`.

Зависимости разрешены только между задачами одного проекта, без циклов и дубликатов. Максимум 100 зависимостей и 100 подзадач. Комментарий содержит 1…4000 символов после удаления пробелов по краям; максимум 500 комментариев на задачу. Заголовки содержат до 180 символов, описания: до 10000. Поля `id`, даты создания и вычисленный `risk` задаёт сервер, отправлять их в форме изменения не нужно. Неизвестные поля в основных схемах отклоняются.

## Ошибки

```json
{"error": "dependency_cycle"}
```

Для ошибок валидации ответ дополнительно содержит `fields` с путём поля и сообщением. Код ошибки стабилен и используется интерфейсом для локализации; сообщения Zod являются диагностическими.

| HTTP | Типичные причины |
| --- | --- |
| 400 | `invalid_input`, `invalid_date_range`, `invalid_dependency`, `dependency_cycle`, `assignee_not_in_project` |
| 401 | `unauthorized`, `invalid_credentials` |
| 403 | `forbidden`, `origin_not_allowed` |
| 404 | Объект отсутствует или проект недоступен пользователю |
| 409 | `email_exists` |
| 413 | JSON превышает лимит 256 КБ |
| 429 | `too_many_attempts`: лимит неудачных входов с одного IP |
| 500 | `internal_error`; детали не раскрываются клиенту |

Проверка `Origin`, SameSite cookie и политика одного источника рассчитаны на интерфейс с тем же адресом, что и API. Публичный кросс-доменный API и долгоживущие ключи доступа не предусмотрены. Для HTTPS включите `COOKIE_SECURE=true`. `ALLOWED_ORIGINS` задаёт допустимые источники для запросов через прокси; эта настройка сама по себе не включает CORS. Ограничения хранилища и единственного экземпляра сервера описаны в [ARCHITECTURE.md](ARCHITECTURE.md).
